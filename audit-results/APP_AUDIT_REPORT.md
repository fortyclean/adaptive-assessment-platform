# تقرير تدقيق التطبيق

## الملخص التنفيذي

تم تدقيق منصة **Adaptive Assessment Platform** بتاريخ 2026-06-23. المشروع يتكون من تطبيق Flutter للهواتف وخادم API مبني بـ Node.js/Express وTypeScript. تم إصلاح خلل في حاويات اختبارات واجهات الإدارة، وتشغيل التحليل والاختبارات والبناء المتاحين محلياً.

## معلومات المشروع والتقنيات

- التطبيق: Adaptive Mastery Platform، تطبيق تقييمات مدرسية تكيفية بواجهة عربية RTL.
- الجوال: Flutter 3.35.7 / Dart 3.9.2، Riverpod، GoRouter، Dio، Hive، SharedPreferences وFlutterSecureStorage.
- الخادم: Node.js 24.17.0، Express، TypeScript، Mongoose/MongoDB وRedis، JWT وbcrypt.
- النسخة: 1.0.99+99.
- المنصات المعرفة: Android وiOS وWeb وWindows (بحسب إعداد Flutter)، وتم بناء Android فقط في هذه البيئة.
- نقطة تشغيل الجوال: `mobile/lib/main.dart`.
- أوامر مكتشفة: `flutter analyze`، `flutter test`، `flutter build apk --release`؛ وفي الخادم `npm run build` و`npm test`.

## بيئة العمل والأجهزة

- Windows 11، Android SDK 36.0.0، JDK Temurin 17.0.19 وGradle 8.14 المتوافق مع Flutter/AGP الحاليين.
- لا يوجد جهاز Android فعلي أو محاكي متصل/مفوض عبر ADB.
- الأجهزة التي اكتشفها Flutter: Windows desktop وMicrosoft Edge فقط؛ لم يُشغَّل التطبيق عليها لأن مسار الفحص المطلوب هو Android.
- لا يوجد محاكي Android جاهز، ولا يعمل خادم محلي على المنفذ 3000 عند الفحص.

## المشكلات حسب الأولوية

### P1 — ملف إعداد إنتاج متعقّب

- السبب الجذري: `backend/.env.production` ظاهر في الملفات المتعقبة ويحمل متغيرات حساسة، منها أسرار JWT والتشفير وبيانات خدمات خارجية. لم تُعرض أي قيمة في هذا التقرير.
- الحالة: غير مُصلح تلقائياً؛ تدوير القيم وإعادة وضعها في مخزن أسرار النشر يتطلب صلاحية على بيئة الإنتاج. لا يكفي حذف الملف محلياً.
- الإجراء المطلوب قبل النشر: تدوير كل القيم الحساسة، إلغاء تتبع الملف مع إبقائه محلياً، وتزويد المنصة بقيم الأسرار عبر secret manager/متغيرات CI.

### P2 — سلامة مجموعة اختبارات الواجهات

- السبب الجذري: بعض اختبارات الودجت تبني `MaterialApp` بلا `AppLocalizations.localizationsDelegates`، فتفشل الشاشات المحلية عند استدعاء `AppLocalizations.of`.
- الإصلاح المنفذ: إضافة اللغة العربية ومفوضي الترجمة واللغات المدعومة إلى حاويتي الاختبار المتأثرتين.
- التحقق: 11 اختباراً مستهدفاً نجح بعد الإصلاح.
- المتبقي: توجد حاويات اختبار قديمة أخرى من النمط نفسه، إضافة إلى اختبارات استكشافية توثق أخطاء سابقة، لذلك لا تزال المجموعة الكاملة غير خضراء.

### P3 — ملاحظات التحليل

- 37 ملاحظة أداء/صيانة من نوع `prefer_const_constructors` في شاشتي تحديات الطالب وملفه الأكاديمي؛ ليست أخطاء تشغيل ولا تمنع البناء.

## الأمن والخصوصية

- تم التحقق من وجود Helmet وCORS ومحددات معدل الطلبات في الخادم.
- ملف المثال `backend/.env.example` متعقب كما هو متوقع، لكن ملف الإنتاج المتعقب يمثل مخاطرة P1 أعلاه.
- لم تُطبع أسرار أو رموز أو قيم من ملفات البيئة أثناء الفحص.
- لم يتم تشغيل فحص ثغرات يعتمد على الشبكة بنتيجة قابلة للتوثيق؛ يلزم تشغيله في CI مع الوصول إلى سجل الحزم.

## UI/UX والأداء

- أظهر اختبار ملف الطالب الأكاديمي السابق انسياباً في الرأس على العرض الضيق بعد علاج Overflow النص؛ الاختبار المستهدف ناجح.
- لا توجد قياسات إطلاق على جهاز فعلي، لذلك لا توجد ادعاءات رقمية عن زمن البدء أو الذاكرة.
- التطبيق يدعم RTL والترجمة العربية/الإنجليزية؛ أخطاء اختبارات الترجمة كانت في حاويات الاختبار لا في المفوضين داخل التطبيق.

## مخاطر وتوصيات قبل النشر

1. عالج P1 بتدوير الأسرار وإخراج ملف إنتاج البيئة من Git قبل أي نشر.
2. وحّد مساعداً لاختبارات الودجت يضيف الترجمة تلقائياً، ثم أصلح الاختبارات المتبقية تدريجياً.
3. عالج ملاحظات `const` بعد استقرار سلسلة الاختبارات.
4. نفذ smoke test على هاتف Android فعلي أو محاكي بعد قبول تراخيص Android وإنشاء AVD.
5. شغّل الخادم مع MongoDB وRedis مخصصين للاختبار ثم نفذ اختبارات API الحية؛ لم يبدأ خادم محلي لأن المنفذ 3000 لم يكن يستمع ولا توجد بيئة اختبار مؤكدة.
